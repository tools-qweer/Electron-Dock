# 可行性状态

更新日期：2026-07-31

## 当前结论

项目已证明 Electron 43 的同一个 `WebContentsView` 可以在主窗口和真实
`BaseWindow` 浮窗之间往返，且不重新加载 Renderer。输入内容、计数器、
滚动位置、WebContents ID 和 WebGL 状态探针在重挂载前后保持一致。

这只是关键架构门槛通过，不等于整个 Qt Dock 行为已经完成。项目现以
`@tools-qweer/electron-dock` 的 Windows x64 Alpha 形式公开；Alpha 入口可供
固定版本试用，但 API、升级策略和人工手感门槛尚未冻结，不能宣称为稳定版
或 Qt Dock 的完整替代。

2026-07-28 首轮人工体验中，用户确认基础浮出、重新停靠和菜单栏修正均无
问题，并确认中心合并、组件四边局部分割和工作区最外沿根级停靠的整体机制
可用。当前结论是“核心机制复刻成功，完整手感尚未验收”：空白未来落位、
起拖距离、指针锚点、尺寸保持和目标切换滞回已按原版继续校准；重启恢复、
混合 DPI 与 100 次往返仍未由用户验收。

## 已由自动化证明

- 布局树创建、分割、标签、移除和恢复的不变量。
- 不可见投放命中能够区分目标组件中心、目标组件四边和主工作区最外沿；
  中心合并到鼠标所在标签组，组件四边只替换目标叶节点，工作区最外沿才
  包裹根布局。
- 目标组件中心按四周内缩 `1/6` 后的 `2/3 × 2/3` 比例区域计算；中心之外
  的角落优先级跟随目标叶节点在拖动前布局中的父分割方向。宽面板不会再因
  固定 96 DIP 边带而把应当局部分割的位置误判成中心合并。
- 拖动命中按移除源面板后的临时布局计算；源面板独占嵌套叶节点、位于多标签
  组或工作区暂时为空时，不会产生重复面板、空节点或失效目标。
- `allowedDropPositions` 会在命中阶段过滤无权使用的方向；无有效目标时没有
  落位预览。
- 每次拖动状态至多产生一个落位高亮模型，不包含可见方向箭头、罗盘或五向
  选择器。
- 边缘落位的未来几何会移除被拖面板的标题和单面板标签；该面板仍由真实
  浮窗承载，因此腾出的区域完全空白，不重复显示标题或业务内容。
- 目标边界使用 5 DIP 滞回，离开边界的轻微抖动不会反复切换目标；保留目标
  仍受 `allowedDropPositions` 约束。
- 相邻叶节点面对同一内部 splitter 的两组边缘命中带，已经按布局树中的
  公共分隔结构归一：水平分隔使用左侧叶节点右边界，垂直分隔使用上侧叶节点
  下边界。指针从分隔线一侧跨到另一侧时应保持同一目标和同一预览几何；嵌套
  T 形分隔按实际接触段选择叶节点。该规则已有自动测试，真实拖动手感仍需
  人工复核。
- 注册面板必须恰好存在一次；标签组最小尺寸取组内全部面板最大值，切换
  活动标签不会让分隔位置跳动。
- 浮窗与停靠区之间按内容尺寸互换：Windows 原生窗框不计入左右停靠宽度，
  上下停靠只补回停靠标题栏高度。左右、上下、局部目标和工作区外沿均已用
  同一套首选像素尺寸求解，不再依赖固定 `30%` 分割。
- 四个边缘方向均有回归测试证明：空间允许时，求解后的新面板表面尺寸等于
  浮窗首选尺寸；空间受限时，只由新面板、相邻面板或嵌套子树的最小尺寸
  夹紧。
- 每次边缘命中保存完整候选布局、候选几何和空白落位矩形；预览与松手提交
  共用同一候选，不在释放时按鼠标位置或百分比二次求解。
- 真实 Electron 隔离 smoke 已贯通
  `beginTransientFloat → dropResolutionAt → setDragPreview →
  commitDockDrop`：局部左侧与工作区外沿左侧都验证预览等于提交结果，并
  保持同一 300 DIP 浮窗内容宽度。
- 同一 smoke 还验证了原生窗口最小尺寸夹紧后的停靠与再次浮出不继续变宽，
  以及无参数 `floatPanel()` 默认按当前停靠客户区尺寸浮出。
- 旧布局缺少新面板时自动补入；重复节点 ID 和序列号碰撞会修复。
- 原子布局文件写入、缺失文件、损坏 JSON、未知版本和回退默认布局。
- 负坐标显示器、窗口部分离屏、显示器拔除和损坏坐标恢复。
- 同一个 WebContents ID 完成“停靠 → 浮动 → 停靠”。
- 四个面板各自只有一个唯一 WebContents；中央标签切换时非活动面板保留，
  不销毁 Renderer。
- 主进程分隔比例变化会重新求解几何并写入持久化队列。
- 两次独立 Electron 进程使用同一临时用户目录：第一次保存分隔比例和真实
  浮窗，第二次确认布局树、浮窗宿主与窗口数量恢复，随后删除临时目录。
- 页面输入、计数、滚动和 WebGL 探针在三种宿主状态间不丢失。
- 简单往返后没有残留 `BaseWindow`。
- IPC 按 shell/panel 的精确 WebContents、主 frame 和页面 URL 分权。
- 主窗口关闭前先终止拖动辅助进程并拆除持久 View。
- 内置演示主窗口与浮窗不会继承 Electron 默认的英文应用菜单；正式接入时由
  宿主应用自行管理主菜单，Dock 浮窗不额外增加菜单栏。
- `0.2.0-alpha.1` 的真实 tgz 消费者已把独立 Shell 工作区挂入已有
  `BrowserWindow`，并验证宿主 WebContents ID、URL、页面运行时状态、菜单、
  close 监听和窗口生命期均未被接管。bounds、显隐、交互开关、面板状态、
  浮出/停靠、sender 预登记和独立 dispose 已贯通。
- `0.2.0-alpha.2` 的真实 tgz 消费者已验证：面板首屏脚本在
  `attachWorkspace()` 尚未返回时调用 `getPanelState()` 仍得到完整非空状态。
  初始化授权按精确 WebContents 与主 frame 校验，只开放状态读取；加载失败、
  同数值 ID 的新 WebContents 和 runtime 并发销毁均有撤权回归测试。
- `0.2.0-alpha.3` 为 Windows 原生拖动链增加异步跨线程窗口定位、坐标去重、
  30 秒 native 上限，以及 Main 侧的强制终止、旧 helper 事件隔离、懒重启和
  窗口生命周期兜底；自动测试覆盖正常取消、失焦、超时、写入失败与重启。
- `0.2.0-alpha.4` 为同一标签组增加 4 DIP 起拖、实时顺序预览、取消回滚和
  持久化换位；增加结构化 Shell 外观与动态更新、公开布局持久化 codec，
  同时把任意 CSS 注入和 smoke-only Panel 快照移出公共合同。生产 Shell
  Renderer 已改为压缩的 React production build。
- 面板公开 preload 的 `getPanelState()` / `onPanelStateChanged()` 包含
  host、active、requestedVisible、实际 visible 和 WebContents ID；
  工作区隐藏或交互禁用时，
  面板自行发起的 float/redock 会被主进程拒绝。
- 原子写失败会保留到 `flush()` / `dispose()` 并向调用方抛出；更新后的完整
  布局成功写入后才会清除已被覆盖的旧失败。
- Windows helper 使用 Framework64 C# 编译器并显式指定
  `/platform:x64`；tracked fallback、构建产物和 tgz 安装结果均校验 PE
  Machine 为 AMD64 `0x8664`。

以上自动检查只能证明可重复断言的状态、几何、IPC、持久化和资源不变量。
它不能证明鼠标锚点没有细微跳动、临时腾位动画与 Qt 一致、半透明高亮视觉
贴合、跨屏 DPI 手感稳定或连续操作没有主观卡顿。

## 已实现、等待真实手势确认

- 标题区域按 Qt 实测值使用 10 DIP 曼哈顿距离开始拖出，普通单击不浮动。
- 停靠面板一次按住可拖成真实系统浮窗。
- 浮出时保持源停靠区域的尺寸，不再统一放大到 320 × 240；标题栏锚点直接
  映射到原生浮窗外框，创建临时浮窗时用 `setContentSize()` 保留业务客户区，
  不把 Windows 非客户区误当作内容尺寸。
- 浮窗可用 Windows 系统标题栏移动；释放在停靠区时回停靠。
- Escape 取消停靠面板的拖出；浮窗系统移动取消后保持浮动。
- Windows 原生坐标转换回 Electron DIP 后再做命中判断。
- 跨显示器 DPI 变化时，辅助程序按当前窗口 DPI 重算指针锚点。
- 拖动中关闭主窗口时强制结束辅助进程，不保留孤儿进程。
- 四个持久面板、嵌套水平/垂直分割、底部活动标签和分隔条调整已实现。
- 投放目标沿用 Qt 式隐形命中，不显示方向提示。任意目标组件中心应整块
  高亮并合并标签；任意目标组件四边应显示唯一局部落位高亮并局部分割；
  目标内部使用 `1/6` 比例锚区并保留拖动前的父分割方向；只有主工作区
  最外沿执行根级停靠。上述真实手势和布局腾位效果等待人工确认。
- 布局保存、损坏回退和启动恢复已实现，等待人工重启确认。

## 尚未实现或尚未冻结

- 稳定版公共 API、跨 Alpha 升级策略和主流框架适配层。
- 已有 `BrowserWindow` 的 `attachWorkspace()` 已进入 Alpha；Dockview 等
  第三方布局框架的兼容适配层仍未实现。
- 完整键盘无障碍、焦点遍历及屏幕阅读器语义。
- macOS、Linux X11 和 Wayland 后端。

## 人工可行性门槛

运行：

```powershell
cd Electron-Dock
npm start
```

依次验证：

1. 分别在“组件层级”“故事场景”和“组件属性”输入独特文本，点击计数并
   滚动列表。
2. 单击任一停靠标题空白处：面板不得闪动或浮出。
3. 按住标题空白处移动达到 10 DIP，一次拖出主窗口；指针锚点不得跳动，
   浮窗尺寸不得突然放大。
4. 松开在主窗口外：应保留真实系统浮窗，输入、计数、滚动和
   WebContents ID 不变。
5. 用浮窗系统标题栏分别移到“组件层级”“故事/地图场景”和“组件属性”的
   中心。界面不得出现方向箭头、罗盘或五向提示；只能整块高亮当前鼠标下的
   目标组件。松手后应加入该组件所在的底部标签组，而不是固定加入中央组。
6. 分别移到上述任一目标组件的左、右、上、下边缘。任意时刻只能看到一个
   局部落位高亮；在宽中央面板中，把指针移到距右边约六分之一的区域时应
   出现右侧空白落位，而不是整块中心高亮。松手后只分割该目标组件，无关
   组件的父子层级不得被包裹。左右空白宽度应与当前浮窗客户区宽度一致；
   上下空白高度应与浮窗客户区高度加停靠标题栏一致。除非相邻区域触发
   最小尺寸约束，松手后的尺寸必须与预览完全相同。
7. 再把浮窗移到主工作区最左、最右、最上和最下外沿。此时应显示根级落位
   高亮，松手后在完整布局最外侧插入；该行为必须与第 6 步的组件局部分割
   明确区分。
8. 在有效目标、无目标和不同组件之间缓慢移动，确认旧高亮立即消失，始终
   最多只有一个高亮；边界附近 5 DIP 内不应闪烁，在无有效目标处松手应
   保持浮动。再沿任意两个相邻组件的公共分隔线左右（或上下）缓慢跨越，
   分隔线两侧和 splitter 本体必须始终是同一个空白落位，不得重新刷新出
   第二个位置。边缘腾出的未来落位必须完全空白，不得出现被拖面板标题。
9. 拖出过程中按 Escape：应回到原停靠区。移动已有浮窗时按 Escape：
   应保持浮动。
10. 拖动两条分隔线、切换“故事场景 / 地图场景”，确认比例与页面状态保留。
11. 关闭并重开应用，确认停靠树、活动标签、浮窗位置和分隔比例恢复；手工
   损坏布局文件后应回退默认四面板布局。
12. 在 100%/125%/150%/200% 的混合 DPI 显示器间拖动，观察锚点、高亮和
    实际释放位置是否一致。
13. 连续往返 100 次后检查窗口数量、响应速度和抖动。
    同一浮窗在左、右、局部目标和工作区外沿之间反复停靠时，宽度不得逐次
    增长或缩小；只有用户实际缩放浮窗或拖动正式分隔条后，下一次首选尺寸
    才能改变。
14. 在拖动过程中关闭主窗口，再确认任务管理器中没有
   `windows-drag-helper.exe` 残留。

第 3、5、6、7、10、12、13 任一项无法稳定达到原版手感，或出现预览与
实际落位不一致、资源增长，则本方案判定失败；不以近似版本继续扩充公用库。
